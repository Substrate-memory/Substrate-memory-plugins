## Install command

```sh
git clone https://github.com/Substrate-memory/Substrate-memory-plugins.git
openclaw plugins install --link ./Substrate-memory-plugins/plugins/openclaw --force
openclaw plugins enable substrate
```

then set `plugins.entries.substrate = { enabled: true, hooks: {
allowPromptInjection: true, allowConversationAccess: true } }`,
`openclaw gateway restart`, verify with `memory_search` in a new turn.

## Parity gaps (explicit)

1. Session hooks are best-effort mappings: `session_end.reason new|reset` ->
   `reset` else `end`; `before_reset` -> `reset`; `session_start.resumedFrom`
   -> `switch` on the old session. OpenClaw has no exact equivalent of Hermes
   `on_session_reset(old,new)` / `on_session_finalize`; mapping is documented
   in README/INSTALL.
2. Tool results are wrapped as `{ content: [{ type: "text", text }] }` where
   `text` is the exact Hermes JSON string (host envelope differs, payload
   identical).
3. Static prompt delivered as `appendSystemContext` (cacheable) instead of a
   Hermes system-prompt section; dynamic block as `prependContext`.
4. Capture POST happens in a detached single-shot `bridge.py` process (sync
   POST, 5 s timeout) rather than an in-process daemon thread — same
   nonblocking guarantee from the agent's perspective.
5. No `server.apiKey` plugin-config option (removed): device onboarding +
   `<home>/.env` + `<home>/substrate/credentials/access-token` (0600) is the
   only file path; headless hosts use `SUBSTRATE_API_KEY` env. Manifest
   description warns never to store secrets in `openclaw.json` (plaintext).
   User-visible onboarding text says "OpenClaw home" (was "Hermes profile").
6. Requires `python3` (3.11+) on PATH; `SUBSTRATE_PYTHON` env wins, then the
   `python` manifest key (wired through `api.pluginConfig`), then `python3`.
   Every handler fails closed without Python. Justification for subprocess
   over pure-JS port: single implementation of contract/client/onboarding
   (no drift), zero npm dependencies.
7. Install is clone-then-`--link` the `plugins/openclaw` subdirectory: a
   `git:<repo>` source installs the repo root, which is not an OpenClaw
   package (INSTALL.md states this). `package.json` test sends a bogus bridge
   command (exit 0 with `invalid_request`) so bridge failures surface.
