# HERMES worker report — MCP memory contract v2 (v0.7.0)

## Decisions (with evidence)

- **Installed identity stays `substrate`.** Verified in the host source
  (READ ONLY): `hermes_cli/plugins_cmd.py::_install_plugin_core` derives
  `installed_name` and the target dir from the manifest `name`
  (`manifest.get("name")`), and `hermes_cli/plugins.py::_parse_manifest`
  uses `data.get("name", plugin_dir.name)` — the directory basename is
  only a fallback. So `plugin.yaml` keeps `name: substrate` (version
  bumped to 0.7.0) while the repo folder is `plugins/substrate-hermes`.
  Existing installs, enable/disable state, and cutover scripts keep
  working; new installs of the new path land in the same
  `<plugins>/substrate/` directory.
- **Turn context injects `block` only.** The `[substrate] … not saved yet`
  sync line is ignored because the Hermes write-ahead spool guarantees
  delivery of every captured turn — there are no missing turns to sync.
  The line exists for spool-less MCP hosts. Documented in CONTRACT.md §13
  and covered by `test_pre_llm_call_injects_block_only_and_ignores_sync_line`.
- **Archive is `substrate-hermes.zip`** (matches `docs/releasing.md`,
  which already names it). Member prefix follows the generic builder
  (`substrate-hermes/`); the installed identity is unaffected (manifest
  name). `substrate-mcp.zip` unchanged.
