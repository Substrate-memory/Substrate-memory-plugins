## Parity gaps (explicit)

1. Completed-turn capture rides a bounded on-disk spool (at most 64 files,
   0600/0700, last-write-wins per stable `event_id`) instead of the Hermes
   persistent 64-slot in-process worker: a hook process is ephemeral, so
   each fire spools the current envelope and a detached sender delivers it
   plus a bounded sweep (oldest first, 10 files per run) of older spool
   files, all with `Idempotency-Key` equal to `event_id`. Residual gap: no
   timed background retry — captures spooled while the server is unreachable
   wait for a later hook fire and expire unsent after 7 days.
2. `PostToolUse` fires per tool call, not per turn. Only one envelope per
   `(session_id, turn_id)` can persist (stable filename + stable
   `Idempotency-Key`), so duplicates are impossible, but the stored turn
   reflects the transcript at the last fire. There is no `Stop`/turn-end
   hook event in 0.144.5.
3. Turn transcript fidelity: the hook reads `transcript_path` (rollout
   JSONL tail, user/assistant `response_item` rows only,
   `<environment_context>` skipped) on a best-effort basis and falls back
   to the hook payload fields; `runtime._capture_envelope` still redacts,
   bounds, and validates everything before sending. Session markers are
   content-free and unaffected.
4. `hooks.json` discovery and top-level shape are CLI-verified
   (`description`/`hooks` only, PascalCase event keys); handler-level keys
   (`timeout_ms`) and the relative-command working directory follow the
   Claude-compatible convention and are tolerated by the parser, but are
   not machine-confirmed — marked best-effort in code and README. If a
   future Codex revision changes the schema, MCP tools and the skill keep
   working standalone.
5. End-to-end auto-firing inside a live model turn is unconfirmed (no API
   auth in the sandbox); hooks were fired manually with real-shaped
   payloads, and the wire schemas come from the binary itself.
