## Parity gaps (explicit)

1. No `on_session_reset` equivalent (explicit host limitation): the Cowork
   host exposes `SessionEnd` but no new-session/reset event, so this plugin
   only ever posts `capture_session` with boundary `end` (the equivalent of
   Hermes `on_session_finalize`) and never emits boundary `reset` with
   `next_session_id` (the Hermes `on_session_reset` marker). Resulting
   behavior: mid-session `/new`-style continuations get a fresh session id
   with clean windows but no explicit old→new session link on the server, and
   `next_session_id`/`parent_session_id` are normally absent (plus
   `SubagentStop` turn snapshots still apply).
2. `UserPromptSubmit` hook input field for the prompt text is read
   defensively (`prompt`/`user_message`/`user_prompt`/`message`) — the exact
   key name is documented in product docs, not in the local cache.
3. Hermes `setup._validate_token` is dead code with a latent `TypeError`
   (`_request` takes no `method`/`json_body` kwargs, and nothing calls it);
   the Cowork `setup.py` fixes the call path instead of copying the bug.
4. Hermes onboarding `_complete` writes only `.env`; the Cowork port also
   mirrors the 0600 `substrate/credentials/access-token` file per the
   multi-host spec (marked patch), since the vendored client reads it first.
